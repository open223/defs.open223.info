# defs-open223-info

Source for <https://defs.open223.info>, the stable-identifier landing page for
ASHRAE 223P concept definitions. The published site is this repository's root,
deployed to GitHub Pages by `.github/workflows/build-site.yml`.

## Contents

| Path | Purpose |
| --- | --- |
| `index.html` | The generated site. Committed, since Pages serves the repo as-is. |
| `constraints.json` | Concept definitions and stable IDs extracted from `ontologies/223p.ttl`. Committed so the site can be rebuilt without re-running the extraction. |
| `ontologies/*.ttl` | Published ontology files, served at `/ontologies/...`. `223p.ttl` is the single input to the site. |
| `templates/` | Jinja template and static assets inlined into `index.html`. |
| `constraints.py` | Port of `publication/constraints.py` from the 223standard repo: finds each concept's SHACL constraints and rules and assigns stable IDs. |
| `build_constraints.py` | Writes `constraints.json` from `ontologies/223p.ttl`. |
| `make_site.py` | Renders `index.html` from `constraints.json`. |
| `check-links.{sh,py}` | Checks that publication links point at anchors that exist. |
| `tests/` | Regression tests for the stable-ID scheme (`make test`). |

## Stable IDs

The publication links to `https://defs.open223.info#<stable_id>`, so the IDs
generated here must match the ones generated by the 223standard publication
build. Both use the same scheme, implemented in `constraints.py`:

- Named resources use their prefixed name, e.g. `s223:Equipment`.
- Blank-node constraints use `b-<label>` where the label comes from
  [RDFC-1.0](https://www.w3.org/TR/rdf-canon/) canonicalization
  (the [`rdfcanon`](https://pypi.org/project/rdfcanon/) package), e.g. `b-c14n42`.
  These depend only on the structure of the graph, so the same graph produces
  the same IDs no matter how it was serialized, parsed, or ordered.

Canonical labels are numbered across *all* blank nodes in the input graph, so
the two sides agree only when they canonicalize the same graph. Keep
`ontologies/223p.ttl` in sync with the `223p.ttl` compiled by the 223standard
repository, and keep `constraints.py` in sync with its upstream copy.

`constraints.json` carries an `ontology` key with the `owl:versionInfo` of the
ontology declaration in `223p.ttl`; `index.html` displays it at the top of the
page so it is clear which build of the ontology the definitions came from.

## Rebuilding

```sh
# 1. drop the new compiled ontology in place
cp /path/to/223standard/223p.ttl ontologies/223p.ttl

# 2. regenerate constraints.json and index.html (needs uv; Python >= 3.12)
make

# 3. optional: run the stable-ID regression tests
make test

# 4. optional: rebuild the 223standard publication and validate its links
make check

# 5. optional: preview locally on :8000
make serve
```

Commit `ontologies/223p.ttl`, `constraints.json`, and `index.html` — pushing to
`main` publishes them.
